# スラロームのパラメータと実機での調整

## ファイル

| ファイル | 役割 | 編集 |
|---|---|---|
| `slalom_profile_designer.py` | シミュレータ。「保存」で `slalom_params.json` に書く | — |
| `slalom_params.json` | 設計値（シミュレータの値）。ターンの表示名 → 速度 → パラメータ | デザイナーから |
| `slalom_tuning.json` | 実機での調整。設計値への**差分**だけを書く | 手で |
| `slalom_presets.py` | ターンの種類（表示名・角度・入口/出口の位置・基準の折れ線）。デザイナーと生成スクリプトで共有 | 種類を増やすとき |
| `slalom_sim.py` | 軌跡の計算・出口のずれ・ずれを0にするオフセット・柱/壁までの余裕。デザイナー・自動調整・同定で共有 | — |
| `slalom_autotune.py` | `slalom_params.json` をまとめて合わせ直す（refit）・ω/α から設計する（optimize） | — |
| `gen_slalom_params.py` | 2つのJSONから `config/slalom_params.hpp` を生成する | — |

生成ヘッダは `build/<preset>/generated/config/slalom_params.hpp` にできる（gitには入れない）。
CMakeがビルドのたびに，JSONか生成スクリプトが変わっていれば作り直すので，`scripts/build.sh` /
`scripts/build_flash.sh` / IDEのビルドのどれでも最新のJSONの値が入る。中身の確認は
`python3 tools/gen_slalom_params.py`（標準出力へ出す）。

## スラロームの組（同じ速度で別の設計を試す）

`slalom_params.json` の速度のキーは `"<速度>[_fan][_<組>]"`（`slalom_presets.py`）。`"500"`（基本の組），`"500_fan"`（ファンON），
`"500_b"` / `"500_fan_b"`（組 `b`）のように，同じ速度・ファンの条件でも組の名前を付ければ別の設計を並べて持てる。

- デザイナーの「ファン」ボタンの右の「組」に英小文字・数字（8文字まで，`fan` は不可）を入れて保存すると，その組に保存される。
  空なら基本の組。読込も今の速度・ファン・組で探す。保存済みの一覧は `500, 500 b, 500 fan` のように出る
- 生成ヘッダの定数名は `S90_500_B` / `S90_500_FAN_B`，メニュー `Slalom` の速度の欄は `500 b` と出るので，そのまま試験できる
- `slalom_tuning.json` の差分も同じキー（`"500_b"`）で書く
- 探索のプリセットは `"slalom": "500_b"` でこの組を選ぶ（`SEARCH.md`）。最短走行（`run_presets.json`）は基本の組を使う

## 調整の流れ

1. デザイナーで設計して保存する（`slalom_params.json`）
2. `scripts/build_flash.sh` で書き込む
3. メニュー `Slalom` → `Slalom left` / `Slalom right` → `fan off` / `fan on` → 速度（`500` / `500 b` …）→ 種類（`S90` / `L90` / `T180` …）を選んで走らせる
   （種類は `slalom_presets.py` の順，速度は昇順に並ぶ）
   - 置き方：機体の後端を区画の後壁に当て，区画の中心線に沿って前へ向ける
   - 入口が区画境界（小回り90°）ならその区画の前の境界，区画中央（大回り90°・180°）なら1つ先の区画中央で曲がり始め，
     出口の基準点から次の区画中央で止まる
   - 入口までの助走は 0.5G で加速する。高速でそれでは助走（小回り90° 132mm，大回り90°・180° 222mm）に収まらないときは，
     助走の3割を等速に残せる最小の加速度に上げる（上限 `MAX_ACCEL_X`＝1.5G，超えるなら走らない）。使った加速度はシリアルに出る
   - 斜めの入口・出口のターン（45°・V90・135°）は試験できない
4. 止まった位置・向きのずれと，シリアルに出る結果を見る

   ```
   slalom result S90_500 right: angle -89.62 deg (target -90.0, error +0.38), distance 391.6 mm (target 390.9, error +0.7)
   ```

   距離の目標は区間ごとの端数（1tick未満）を含まないので，誤差が+1mm程度出るのは正常。
   ログは `tools/log/slalom/<name>_<left|right>.csv`
5. `slalom_tuning.json` に差分を書き，2へ戻る

```json
{
  "小回り90°": {
    "500": {
      "base_saved_at": "2026-10-02T03:34:10",
      "delta": { "Set_pri_offset": -2.0, "Set_post_offset": 1.5 },
      "delta_left": { "Set_post_offset": 3.2 },
      "note": "出口で右に1mmずれる。電池8.1V"
    }
  }
}
```

- キーは `slalom_params.json` と同じ（表示名 → 速度）
- `base_saved_at` は調整したときの設計値の `saved_at`。デザイナーで保存し直すと一致しなくなり，**ビルドがエラーで止まる**
  （古い差分を新しい設計値に足さないため）。差分がまだ有効なら新しい `saved_at` に書き換える
- `delta` は左右どちらの旋回にも足す。`delta_left` / `delta_right` は左旋回だけ・右旋回だけに足す（`delta` に重ねて足す。
  上の例の左旋回の post_offset は +1.5 + 3.2 = +4.7mm）。どれも省略できる
- 使えるキーは `Set_low_AngVel` / `Set_Low_AngAcl` / `Set_pri_offset` / `Set_post_offset`（速度は表のキーなので変えられない）。
  知らない項目・キー（綴りの間違いなど）はビルドがエラーで止まる

## 横滑りの係数（c, K）の同定

`tools/identify_slip.py` が，走行ログと定規で測った停止位置のずれから c, K を求める（デザイナーでの初期値はいらない）。

1. スラロームを走らせ，止まった位置の区画中央からのずれを測る：出口方向に直交する方向（ターンの外側＝入口と反対側が正）と，
   出口方向（目標より先が正）
2. `tools/slip_measurements.json` に1行足す（ログのファイル名から種類・速度・ファン・向きを読む）

   ```json
   {"log": "slalom/L90_500_right.csv", "outward": 10, "longitudinal": -8, "note": "ファンOFF，BACK_TO_AXLE_MM=42"}
   ```

   `tools/main.py` は同じ名前のログがあると `_1`, `_2`, ... と連番を付けて残す（既定）ので，保存された名前を書く。
   `BACK_TO_AXLE_MM` を変える前の走行には `"back_to_axle_mm": 25` のように走ったときの値を書く
3. `python3 tools/identify_slip.py` を実行する。ファンON/OFFごとに，走行ごとの c_eff，c だけ（K=0）の値，
   2つ以上の速度があれば c と K，その c, K で合わせ直した各パラメータの値が出る
4. `python3 tools/slalom_autotune.py refit --fan off --c <c> --k <K> --write` で設計し直す（下の「自動で設計し直す」）

1つの速度からは c_eff = c + K·v² しか決まらない。K を求めるには速度を大きく変えた走行（例 300 と 1000mm/s）を足す。

## 走らない（LEDバーが左右交互に点滅する）とき

シリアルに理由が出る。

- `rejected (accelLimit)` … 角加速度が `config::profile_limit::MAX_ALPHA` を超えている
- `rejected (tooShort)` … 最大角速度まで加速しきれない（生成スクリプトでも止まる）
- `diagonal entry/exit` … 斜めのターンは試験が未対応

## 注意

- `config::mouse::BACK_TO_AXLE_MM`（`Core/Inc/config/mouse_config.hpp`，機体の後端から車軸まで，42mm）がずれていると
  入口の位置がずれ，その分を `pre_offset` の調整で吸収してしまう。メニュー `Slalom` → `Axle check` → `n=1/2/4/8` で確かめる：
  車軸（車輪の中心）を床の線の真上に置くと，`BACK_TO_AXLE_MM + 90·n` 走って後端が90·n先の線の上で止まるはず。
  線より先に止まった量をδとすると，本当の値は `BACK_TO_AXLE_MM − δ`（δがnに比例して増えるならエンコーダの距離の誤差）
- デザイナーの滑り係数は軌道の予測だけに使うもので，実機には渡さない（機体幅 `Set_Width` も同じ）。
  スリップ角（速度の向きが機体の向きより外側へ遅れる角）は β = K·v·ω + c·ω/v（v [m/s]，ω [rad/s]，c [m]）：
  - `Set_K_SP`（K）… 横加速度 v·ω に比例する滑り（タイヤの横方向の弾性）
  - `Set_C_SP`（c [mm]）… 速度によらない横滑り（車軸の横すべり速度 c·ω。車軸より c 前の点を中心に回るのと同じ）
  - 2026-10-02 の実機（ファンOFF，右旋回5本）は c ≈ 10.5mm，K = 0 でずれをRMS 2mmで再現した。K だけで合わせると
    500mm/s で約0.04，700mm/s で約0.02 と速度で変わった
- 滑り係数はファンの有無で変わるので，デザイナーの「ファン: ON/OFF」を走る条件に合わせて保存する。
  ファンONは速度のキーに `_fan` が付き（`"500_fan"`），同じターン・速度でもファンOFF（`"500"`）と別々に持つ。
  ボタンで切り替えると，その条件の保存データがあれば読み込む。`slalom_tuning.json` のキーも同じ（`"500_fan"`）。
  生成ヘッダでは `L90_500_FAN`（メニューは `fan on` → `500` → `L90`）になり，試験はファンを `config::fan::RUN_DUTY`（20%）で回して走る
- メニューに並べられるのは，ファンON/OFFそれぞれの速度（組を含む）・1速度あたりの種類とも `config::menu::MAX_CHILDREN`（10）個まで。
  超えるとビルドが止まる。種類は8つなので，増えるのは速度の数の方（ファンON/OFFで別々に10個まで）

## 自分で調整を回す手順（ずれの測定 → 同定 → 設計し直し）

1. **走らせて測る**：メニュー `Slalom` → 向き → ファン → 速度 → 種類で走らせ，止まった位置の区画中央からのずれを測る。
   出口の向きに直交する方向（ターンの外側＝入口と反対側が正）と，出口の向き（目標より先が正）。ログは
   `tools/log/slalom/<名前>_<向き>[_n].csv`（同じ名前は連番で残る）
2. **記録する**：`tools/slip_measurements.json` に1行足す
   `{"log": "slalom/L90_500_right_1.csv", "outward": 3, "longitudinal": -2, "note": "..."}`
3. **同定する**：`python3 tools/identify_slip.py`。ファンON/OFFごとに c（2つ以上の速度があれば K も）と残差が出る。
   残差RMSが測定のばらつき（2〜3mm）程度ならモデルは合っている。ずっと大きい・特定のターンに偏るなら，
   置き方（`BACK_TO_AXLE_MM`）や制御（ログ）を先に疑う
4. **設計し直す**：`python3 tools/slalom_autotune.py refit --fan off --c <c> --k <K>` で「今 → 新」を確かめてから
   `--write` を付けて書く（下の「自動で設計し直す」）。デザイナーで1つずつ直すなら，ターンと速度を選んで「読込」，
   「滑り係数 K」「滑り係数 c(mm)」に 3 の値を入れ，「→ 入口 … / 出口 … で 0」の値を入れて保存する
5. **書き込んで確かめる**：`scripts/build_flash.sh` → 1 に戻る。ずれが測定のばらつき程度に収まれば完了。
   残ったずれも 2 に足していけば c の推定が確かになる（ログの実際の動きから計算するので，設計を変えた後の走行も使える）

## 自動で設計し直す（`slalom_autotune.py`）

デザイナーと同じ計算（`slalom_sim.py`）で，`slalom_params.json` のエントリをまとめて設計し直す。既定は「今 → 新」の表
（ω・α・pre・post・出口のずれ・柱/壁までの余裕・時間）を出すだけで，`--write` を付けたときだけ書く。
書くと saved_at が新しくなるので，そのエントリに `slalom_tuning.json` の差分があればビルドが止まる（一覧が出る）。
差分は古い設計に対する補正なので，見直して消すか `base_saved_at` を書き換える。

- **refit**（c・K を変えた後）：ω・α の形を保ったまま出口のずれを 0 にする。`--c` / `--k` を省くと各エントリの保存値を使う
  - S90・L90・斜め：出口の位置は pre/post_offset に対して正確に1次なので，2x2 の1次方程式で厳密に解く
  - T180：入口と出口が平行で，オフセットでは前後しか直らない。加減速の角度の割合を保ったまま ω を変えて外側のずれを 0 にし，
    pre は今の値のまま post で前後を直す
  - オフセットが負になるもの（ω・α を変えないと合わない）は書かずに「✗」を出す → optimize を使う
- **optimize**（新しく設計する）：(ω, 加減速の角度の割合) を格子で探し，各点で出口のずれを 0 にしたうえで，制約
  （α ≤ `--alpha-max`＝既定は `MAX_ALPHA`，ω ≤ `--omega-max`，pre/post ≥ `--min-offset`＝既定 0，余裕 ≥ `--margin`＝既定 8mm）
  を満たす中で最短時間のものを探す。最短時間だけだと α がいつも上限に張り付くので，最短から `--slack`（既定 1%）以内に
  遅いだけの候補のうち α が最小のものを選ぶ。ターン・速度は `--turn S90 L90 --speed 700` で絞れる
- **新しい速度を作る**：`--create` を付けると，`--speed` のうち無い速度のエントリを作ってから設計する。斜めのターンも同じ。
  種は，同じターン・同じファンのいちばん近い速度 → 同じターンのもう一方のファン（どちらも ω を速度比倍，α を速度比²倍）
  → そのターンの設計が1件も無ければ既定の初期値（optimize のときだけ。refit は形を保つので元の設計が要る）。
  optimize は ω・α を探し直すので，結果は種によらない。設計できない（✗）ものは作らない。例：
  `python3 tools/slalom_autotune.py optimize --fan on --c 0.7 --k 0.0071 --speed 300 600 900 1200 1500 1800 2100 --create --write`
- 横加速度（v·ω）の上限はまだ無い。高速では数Gになる設計も出るので，実機では低速から順に試す
- **左右で滑りが違うとき**：`refit --side left`（または `right`）で，その向きだけを設計し直し，`slalom_params.json` は変えずに
  `slalom_tuning.json` の `delta_left` / `delta_right` に差を書く（両方向の `delta` があれば，それを引いた残り）。もう一方の向きは今の設計のまま。
  例：`python3 tools/slalom_autotune.py refit --fan off --c 0 --k 0.0061 --side left --turn S90 L90 T180 --write`
- refit・optimize とも，書く前にファームウェアの `slalom::validate()` と同じ検査をする（0 でない直線・角速度の区間が
  1制御周期 `DT_S` 以上，α ≤ `MAX_ALPHA`，等角速度の区間が1制御周期以上）。通らないものは書かない
  （通らない設計を書くと，探索・最短走行のプリセットの `static_assert` でビルドが止まる）
- **余裕**は，機体の横幅の線（デザイナーの灰色の線の間）と，柱・ありうる壁（基準の折れ線が通り抜けない区画境界）との
  最小距離。機体の前後の角は見ていないので，`--margin` は角の張り出しの分を含めて決める
- 例：`python3 tools/slalom_autotune.py optimize --fan off --turn T180 --margin 10`
- 2026-10-05 より前のデザイナーは，加速フェーズの最後の1歩（v·dt = 0.5〜0.9mm）を出口の位置に足していなかった
  （経路長には入っていた）。それより前に保存した設計は出口が最大 1mm ほどずれているので，`refit`（c・K は保存値のまま）で直る

速度を足すとき（例 200mm/s）は，既存の設計の ω を 速度比 倍，α を 速度比² 倍にすると同じ軌跡になる。
滑りが c だけ（K = 0）なら滑る量も速度によらないので，オフセットもそのまま使える。
