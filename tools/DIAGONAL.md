# 斜め走行のセンサーのデータ収集

参考：naophis「斜めの姿勢制御をするには」（Mice Advent Calendar 2018，<https://naophis.hatenablog.com/entry/2018/12/08/diagonalrunning>）。

斜めの直線では横壁の中心線の値（`config::wall::REF_*`）が使えない。記事の方法では、45° のセンサーが壁・柱の
**切れ目**を検出したところからの距離に対するセンサー値を表（理想のリファレンス値）にしておき、走るときはその距離での
表の値を目標にして制御する。ここでは表を作るためのデータ収集・解析と、機体で切れ目からの距離を数える部分を作った
（表を使った制御はまだない）。

## 幾何

斜めの直線（区画の辺の中点を結ぶ線）では、柱が経路から 90/√2 ≈ **63.6 mm** 横にあり、内側（曲がった向き）と
外側に交互に 90√2 ≈ **127.3 mm** おきに並ぶ。同じ側の柱は 180√2 ≈ **254.6 mm** おき（記事の表の横軸 0〜250 と同じ）。

入45°の出口の基準点（区画の辺の中点）を `diag_x = 0` とすると、柱は

| 側 | 柱の位置（diag_x） |
| --- | --- |
| 内側（右へ入ったら右） | −63.6, 190.9, 445.5, 700.0, … |
| 外側 | 63.6, 318.2, 572.8, 827.3, … |

この機体の横のセンサー（irL / irR）は前へ約 45° 向いている（直進では区画境界の約 91 mm 手前で壁切れを検出する）。
斜めの直線ではビームが迷路の縦横の向き（右へ入ったら左は北、右は東）を向き、前にある壁の面が柱で切れたところで
値が急に下がる。これが記事の「45度センサーの切れ目」にあたる。記事の真横 90° のセンサーはこの機体にないので、
前左・前右（irFL / irFR）も記録しておき、表に使えるかをデータで見る。

## 試験メニュー：Device → IR → Diagonal

| 項目 | 内容 |
| --- | --- |
| left n4 / right n4 | 入45°（IN45_500）で左 / 右へ入り、斜めの直線を 4 区間（509 mm）走って止まる |
| left n8 / right n8 | 同じく 8 区間（1018 mm）。表のデータはこちらで取る |

走り方：置き方は探索と同じ（後端をスタート区画の後壁に当てて北向き）。1区画先の区画中央まで 500 mm/s に加速し、
入45°で斜めに入る。辺の中点の間隔（127.3 mm）を n 区間ぶん 500 mm/s のまま走り、最後の区間の後半（63.6 mm）で
減速して n 個先の辺の中点で止まる。横壁の補正・壁切れの補正は使わない。

ログ：`diag/IN45_500_<left|right>_n<n>.csv`。バッファを斜めの区間に使うため、出口の基準点の 100 mm 手前で
ログを取り直す（助走と旋回の前半は入らない）。n8 は 10 列 × 約 3 ms おき（500 mm/s で約 1.5 mm おき）、
n4 は約 2 ms おき。

| 列 | 内容 |
| --- | --- |
| `diag_x` / `target_diag_x` | 出口の基準点からの実測 / 目標の距離 [mm] |
| `angle_error` | 実測 − 目標の角度 [deg]（斜めの直線は向きの補正なしで走るので、ずれの大きさを見る） |
| `ir_l` `ir_fl` `ir_fr` `ir_r` | センサーの値（左・前左・前右・右） |
| `since_l` / `since_r` | 機体の `DiagEdge` が数えた、最後の切れ目からの距離（まだなければ NaN） |

シリアルには、走る前に柱の位置の一覧（`pillars (diag_x ...)`）、止まった後に止まった位置・角度のずれ・
切れ目の数・ログの長さ（`FULL` と出たら最後が欠けている）が出る。受け取りは `tools/main.py`、取りこぼしたら **LogDump**。

## 壁の並べ方

スタート (0,0) から北へ置き、区画を (列, 行) で書く（右へ入るとき。左へ入るときは左右を反転し、スタートを
右から 5 列目以上に置く）。経路が通る辺は開けておく。

### A. のこぎり（基準）

経路が通る区画の、通らない 2 辺を全部壁にする。両側の柱すべてに壁があり、波形が最もきれいに周期的になる。

| 区画 | 入る辺 → 出る辺 | 壁にする辺 |
| --- | --- | --- |
| (0,2) | 南 → 東（入45°） | 西・北 |
| (1,2) | 西 → 北 | 南・東 |
| (1,3) | 南 → 東 | 西・北 |
| (2,3) | 西 → 北 | 南・東 |
| (2,4) | 南 → 東 | 西・北 |
| (3,4) | 西 → 北 | 南・東 ← n4 はこの区画の西の辺の中点で止まる |
| (3,5) | 南 → 東 | 西・北 |
| (4,5) | 西 → 北 | 南・東 |
| (4,6) | 南 → 東 | 西・北 ← n8 はこの区画の東の辺の中点で止まる（(5,6) に鼻先が入る） |

(0,0)・(0,1) は北の辺を開ける（横の壁はあってもなくてもよい）。

### B. 壁の抜け（変化を見る）

実際の迷路では、柱に付く壁は 1 枚以上というだけ（規則 2-4）。A から 1 枚ずつ抜いて同じ走行をし、
どの壁が切れ目と表の形を決めているかを見る。たとえば (2,3) の東、(2,4) の北を抜く。抜いた壁の前後で
切れ目が消える・ずれる区間を `diag_sensor.py` の位相の表で確かめる。

## 解析：tools/diag_sensor.py

```sh
python3 tools/diag_sensor.py                         # tools/log/diag/*.csv をまとめて
python3 tools/diag_sensor.py tools/log/diag/IN45_500_right_n8.csv --plot
python3 tools/diag_sensor.py --on 600 600 --off 450 450   # 閾値（左 右）を変えて検出し直す
python3 tools/diag_sensor.py --selftest               # 合成データでの確認（ロボットなし）
```

出るもの：

- 走行ごと：止まるまでの範囲、サンプルの間隔、向きのずれの最大（2° を超えると警告）
- 左右の切れ目：位置、間隔（254.6 mm のはず）、**その側の柱からの位相**、機体の `DiagEdge` との差
- 位相のまとめ（全走行・左右の入り方をまとめて）と、走行ごとの**前後・横の分解**：
  横に d（左が正）ずれると、左のビームは柱を d 遅れて、右のビームは d 早く過ぎる（45° なので 1:1）。
  距離のずれは左右とも同じ向きに動かす。そこで 前後 = (左の位相 + 右の位相)/2、横 = (左 − 右)/2。
  前後の std が小さければ切れ目は位置の基準として使える。横は入45°の出口の横のずれ
- 閾値の提案：横のセンサーの値の 5%〜95% の 40% / 60% の高さ（`config::diag` に入れる値の目安）
- 表：センサーごとに、切れ目からの距離（2 mm ごと）に対する平均・標準偏差・サンプル数。切れ目と切れ目の間の
  周期だけを使う（最後の切れ目より後は、並べた壁の先を見ているか減速中で、周期の形にならない）。
  切れ目の直後 10 mm・直前 15 mm（`--guard`）とサンプルの少ない区間は「使わない」（`*`）。
  ばらつき・傾きでは決めない：切れ目の手前は値が急に増えて走行ごとのばらつきも大きいが、横のずれへの感度が最も高い
- `tools/log/diag/reference.json`：表（`since` / `mean` / `std` / `n` / `use`）、位相、走行ごとの前後・横、閾値

左右どちらへ入った走行でも、左のセンサーは左の切れ目、右のセンサーは右の切れ目からの距離で表にするので、
同じ表にまとめられる（左右の入り方で柱の内側・外側が入れ替わるだけ）。

## 入45°の横のずれ（R2 の結果から）

右へ入ると右（内側）へ約 9 mm、左へ入ると左（内側）へ約 6 mm ずれている。入45°は入口が区画中央なので、旋回を
δ 早く始めると斜めの直線全体が元の向き（北）へ δ 戻り、斜めの直線に対して内側へ δ/√2・後ろへ δ/√2 ずれる。
pre_offset を +δ にすると直線は外側へ δ/√2・前へ δ/√2 動き、post_offset を −δ/√2 にすると出口の基準点が
直線に沿って δ/√2 戻る（横は変わらない）。この組で横だけを直し、前後は変えない（前後のずれはまだ測れていない：
位相の −82.4 mm にはセンサーの取り付けの分が入っている）。

## 今後

- 表を使った制御：切れ目からの距離 `diagEdge.since()` で表を引き、横のセンサーの値との差を向きの補正にする
  （`WallControl` の斜め版）。記事のように不安定な区間は使わない
- 表の生成：`reference.json` から `config/diag_reference_table.hpp` を生成する（`gen_front_distance.py` と同じ形）
- 切れ目の位相が安定していれば、斜めの直線でも壁切れの補正（`WallEdge`）と同じように並進の位置を合わせられる
- 速度による差（検出の遅れ）：700 mm/s の入45°で同じ走行をして位相を比べる
