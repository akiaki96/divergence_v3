# 最短走行（Run → Fast）

探索して保存した迷路（`app/maze_store`）の既知の壁だけを使い、`external/micromouse_simulator` の
`time_based_dijkstra` が求めた最短時間の経路を走る。ゴール区画で止まる（スタートへは戻らない）。

## ファイル

| ファイル | 役割 | 編集 |
|---|---|---|
| `run_presets.json` | 最短走行の直線のプロファイル（`"straights"`：最高速度・加減速度）とプリセット（`"presets"`：ターンの速度・既定の直線・斜めを使うか・ファン） | 手で |
| `gen_run_presets.py` | `config/run_presets.hpp` を生成する。使うスラロームが設計されていなければビルドを止める | — |
| `Core/Src/app/fast_plan.cpp` | ソルバーの ACT の列を、直線（台形）とスラロームの手順に直す（HAL に依存しない） | — |
| `Core/Src/app/fast_run.cpp` | 保存した迷路の読み込み、経路の計算、走る前の検査、走行とログ | — |

プリセットの例（`run_presets.json`）：

```json
{
  "straights": {
    "1500_a3k": {"max_speed": 1500, "max_speed_dia": 1000, "accel": 3000, "decel": 3000, "note": ""},
    "2500_a8k": {"max_speed": 2500, "max_speed_dia": 1800, "accel": 8000, "decel": 8000},
    "4000_a12k": {"max_speed": 4000, "max_speed_dia": 2800, "accel": 12000, "decel": 12000, "fan_only": true}
  },
  "presets": {
    "500": {"turn_speed": 500, "straight": "1500_a3k", "diagonal": false, "wall_edge": true, "note": ""},
    "1800_dia": {"turn_speed": 1800, "speeds": {"S90": 900, "IN45": 1500, "V90": 1200},
                 "straight": "2500_a8k", "diagonal": true, "wall_edge": true}
  }
}
```

### 直線とターンを別々に選ぶ

- **直線のプロファイル**（`"straights"`）は縦横・斜めの最高速度と加速度・減速度の組。名前は英数字と `_`（メニューの表示とログのファイル名）。
  `"fan_only": true` は吸引で滑りを抑える前提の加速度で，ファンを回すプリセットとだけ組み合わせる（ファンなしで選ぶと走らない）
- **プリセット**（`"presets"`）はターンの速度などと，**既定の直線**（`"straight"`：直線の名前）を持つ
- メニューの `Run` → `Fast` → `straight` で直線を選ぶと，その後の最短走行は**どのプリセットもその直線で走る**（電源を切るまで覚えている）。
  `preset` を選ぶとプリセットの既定の直線に戻る。選んだときは LED を番号の分だけ点ける（`preset` は1つ，1つ目の直線は2つ…）
- 直線の最高速度はターンの速度を下回れないので，組み合わせたときに**いちばん速いターンの速度まで引き上げる**
  （縦横はすべてのターン，斜めは斜めのターン。`turn_speed` が下限。`withStraight`，`app/run_preset.hpp`）。
  例：`1200_dia` に既定の `1500_a3k`（斜め 1000）→ 斜めは 1200
- どのプリセットとどの直線の組み合わせも走れることをビルド時に確かめる（加減速度の上限など。`fast_run.cpp` の `static_assert`）
- 直線を選んで走ったときのログは `fast/<preset>_<straight>_trace`・`_edges`（選んでいなければ今までどおり `fast/<preset>_trace`）。
  シリアルのプリセットの行にも `straight <名前>` が出る

今の直線（`run_presets.json` の順＝メニューの順）：

| 名前 | 縦横 / 斜め [mm/s] | 加速 / 減速 [mm/s²] | 既定にしているプリセット・メモ |
|---|---|---|---|
| `1000_a2k` | 1000 / 700 | 2000 / 2000 | 慎重（初めての迷路・壁の補正の確かめ） |
| `1500_a3k` | 1500 / 1000 | 3000 / 3000 | 300〜900，1200_dia，500_fan40 など（実機で走った 500 / 500_dia の直線） |
| `2000_a4k` | 2000 / 1200 | 4000 / 4000 | 1200_s900 |
| `2000_a8k` | 2000 / 1500 | 8000 / 8000 | 1500 |
| `2500_a8k` | 2500 / 1800 | 8000 / 8000 | 1800，2100 |
| `3000_a8k` | 3000 / 2000 | 8000 / 8000 | |
| `3000_a6k_d10k` | 3000 / 2000 | 6000 / 10000 | 加速は控えめ（電圧・滑り），減速は強め |
| `3500_a10k` | 3500 / 2500 | 10000 / 10000 | ファンのときだけ |
| `4000_a12k` | 4000 / 2800 | 12000 / 12000 | ファンのときだけ。加速の終わりは電圧で頭打ちになりうる |
| `free_a5k` | 上限なし（9000） | 5000 / 5000 | 直線をすべて加減速に使う三角形 |
| `free_a8k` | 上限なし（9000） | 8000 / 8000 | 以前の `*_free` プリセット（`500_free` → `500` + `free_a8k`） |

- 2026-10-11 に整理：プリセットに直に書いていた `max_speed`〜`decel` を名前付きの直線にまとめ（値は変えていない），
  `*_free` の8個は「元のプリセット + `free_a8k`」と同じなので消した。3000 以上・`free_a5k`・非対称の加減速は新しく足した（実機で未試験）
- 高い速度では，走った後の `fast/<preset>_<straight>_trace` の目標と実測の速度（`target_velocity_x` / `current_velocity_x`）と
  `left_duty` で電圧の飽和を確かめる（加速 8000 では電池が 5.5 V まで下がると約 4.8 m/s が上限の見込み）

- **ターンの速度は種類ごとに決める**。既定は `turn_speed`，`"speeds"` で種類（S90 L90 T180 IN45 OUT45 V90 IN135 OUT135）
  ごとに上書きする。大回り90°（L90）・180°（T180）は必ず、`"diagonal": true` なら入45°・出45°・V90°・入135°・出135° も
  （`slalom_params.json` にその速度・ファンの条件の設計がなければビルドが止まる）
- **速度を落とす候補**：各種類のいちばん速い候補がその速度の設計で，同じ種類・同じファンの条件のもっと遅い設計（基本の組）が
  すべて下の候補になる（`config::run::LADDER_*`）。走る経路で，あいだの直線が短くて速度を変えきれない
  （ターンどうしが直線なしで続くなら同じ速度でなければならない）ところや，スタート直後（置いた位置から最初の区画中央まで 42mm）・
  ゴール直前で加速・減速しきれないところは，`fast_plan::fitSpeeds` が速い方のターンを下の候補に落とす（変わらなくなるまで繰り返す）。
  基準は機体の上限（`MAX_ACCEL_X` 1.5G・`MAX_DECEL_X` 2G）で，`validate` と同じ（短い直線は台形を作れず，1区間で速度を変えるため）。
  いちばん遅い候補でも合わなければ `turn speeds cannot be bridged` で走らない。ランダムな迷路 300 個で，1800_dia は
  ターンの約 41% が下の候補に落ちるが，1500_dia より平均 0.19s 速い
- 小回り90°（S90）は斜めなしなら必須。斜めありなら任意（`speeds` に書かなければ `turn_speed` の設計があれば使う，
  書けばその速度で必ず使う，`"s90": false` なら使わない）。S90 が無いときはソルバーの S90 のコストを 30000ms にして
  ジグザグを斜めで走らせる（ランダムな迷路 461 個で経路を失わず，平均 48ms 遅いだけ）
- V90 も `"v90": false`（斜めありのときだけ）で使わないようにできる（コストの扱いは S90 と同じ）。ただし S90 も V90 も
  無いと，ランダムな迷路 300 個のうち 115 個で走れない（経路なし 42，V90 を選んでしまう 73）。今のプリセットでは使っていない
- 以前の `"s90_speed"` は `"speeds": {"S90": …}` に，`"start_speed"` は下の候補への自動の置き換えになった（書くとエラー）
- 直線は隣のターンの速度で入って出る台形（最初は 0 から、最後は 0 まで）。最高速度は縦横 `max_speed`、斜め `max_speed_dia`（直線のプロファイルの値。上の引き上げの後）
- ソルバーの時間のコスト（`fast_plan::applySolverCosts`）は、各種類のいちばん速い候補の経路長（`slalom::totalDistance` の
  左右平均）/ その速度。直線は `turn_speed` で入って出る台形の近似（下の候補に落ちたところは実際より短く見積もる）
- `"fan": true` ならファンを回して走り、ターンもファンONの設計を使う
- `"fan_duty": 0.4`（`"fan": true` のときだけ。省略で `config::fan::RUN_DUTY`＝0.2）で回す duty を変えられる。ターンは RUN_DUTY で設計したファンONの設計のまま（吸引が強いと滑りが減り、出口が少し内側に寄るかもしれない）。メニューでは duty ごとに別の段（`fan 0.4`）になる。0.4 は回し始めに電池が 6.6 V 前後まで下がる（`tools/log/fan_vsag_m2`）
- 横壁の補正（探索と同じ `common/wall_control.hpp`）は縦横の直線だけでかける（`fast_plan::orthogonalRanges`。前のターンの出口の基準点から次のターンの入口の基準点まで、目標の位置で判定）。斜めの直線とスラロームのオフセット（入45°の出口側・出45°の入口側などは斜め）では横壁を読めないのでかけない。`config::wall::FAST_RUN_CONTROL` を false にすると切れる。補正で蛇行するとエンコーダの距離ほど前へ進まず、ターンの入口に届かなくなりがちなので、壁切れの補正（下）と合わせて使う
- `"wall_edge": true`（省略で false）なら、区画中央から入るターン（L90・T180・IN45・IN135）の前で壁切れの補正をかける（下の「壁切れの補正」）

## 走らせるまで

1. **探索して迷路を保存する**：`Run` → `Search`（ゴールの後は走りながら定期的に，スタートに戻ると「探索し終えた」として保存される。途中で止まっても最後の保存で走れる）。`Run` → `Maze` → `Show` で確かめられる
2. **最短走行**：機体の後端をスタート区画 (0,0) の後壁に当てて北へ向け、`Run` → `Fast` → `fan off` / `fan on` / `fan 0.4` → `ortho`（縦横だけ）/ `diagonal`（斜めあり）→ プリセットを選ぶ（どの段も `config::menu::MAX_CHILDREN`＝12 個まで）。
   直線を替えるなら先に `Run` → `Fast` → `straight` → 直線を選んでおく（上の「直線とターンを別々に選ぶ」）
   - まず `"500"`（斜めなし）から。斜めのターンは実機で試していない
   - 走る前にシリアルへ、使う迷路（面・番号・ゴール）、経路の手順（直線の長さ・ターン）、推定時間が出る
   - 次のときは走らずに、LEDバーが左右交互に点滅する（理由はシリアルに出る）：保存した迷路がない、
     既知の壁だけではゴールまでの経路がない、プリセットにないターンが要る、区間を積めない（加速度の上限など）
3. **ログ**：止まったら機体を持ち上げて置く（`haltByAccZ`）と、`fast/<preset>_edges`（壁切れごとに1行）と
   `fast/<preset>_trace`（目標・実測の位置と角度、`edge_shift` は壁切れの補正の累計、`wall_offset` は横壁の補正が足した向きの累計 [deg]）を送る。シリアルには縦横の直線の範囲（`wall control on, N orthogonal straights`）も出る

## 壁切れの補正（区画中央から入るターンの前）

大回り90°・180°・入45°・入135° は区画中央から曲がるので、入口の位置がずれるとターン全体（斜めに入るターンでは
その後の斜めの直線も）がずれる。そこで、その手前の縦横の直線で横壁が切れたところ（`common/wall_edge.hpp`、探索と同じ）で並進の実測位置を区画境界に合わせる。

- 教える境界は、ターンの入口（区画中央）の半区画手前の境界と、さらに1区画手前の境界（ターンごとに最大
  `config::wall_edge::FAST_BOUNDARIES_PER_TURN` = 2 個）、それに**入口の半区画先の境界（入口 + 90）**
  （`FAST_CENTER_BOUNDARY`）。走った後にシリアルへ位置の一覧が出る
- 入口 + 90 の壁切れは、横のセンサーが車軸の約 91 mm 先を見るので、区画中央（入口）に着いたところ（入口の約 1 mm 手前）で
  起きる。ターンの先の区画は曲がる側の壁がないので、入口の区画に曲がる側の壁があれば必ず切れる（手前の境界は
  「1区画手前まで壁があり、入口の区画で壁がない」ときだけ）。直前の直線が 41 mm 以上あれば教えるので、
  ターンの直後の 1 区画の直線でも使える。ただし窓（前 20 mm／後ろ 40 mm）の後ろ側はターンが始まった後（入口オフセットは
  900 mm/s の L90 で約 1 mm）なので、予想より遅れた壁切れは検出できず補正しない
- 斜めから入るターン（出45°・出135°・V90）の前では使わない。手前が斜めの直線で、横のセンサーには柱が
  ちらっと見えるだけで、区画境界で壁が切れる形にならない（斜めの直線の壁切れも記録だけ）
- 壁切れは境界の約 91 mm 手前（`OFFSET_*`）で検出するので、その位置が直線の中にない境界は使わない
  （ターンの直後の 1 区画の直線の、入口の手前の境界など）。教えていない境界の壁切れ（長い直線の途中など）は記録だけで補正しない
- 横壁が切れない境界（その先も壁が続く、手前も壁がない）は何もしない。窓（予想より前は `WINDOW_MM` 20 mm，後ろは `FAST_WINDOW_LATE_MM` 40 mm）から外れた壁切れも使わない
- 境界は実測の位置が 300 mm 手前に来てから教える（`WallEdge` が同時に待てる境界は 4 つ）
- 確かめること：`fast/<preset>_edges` の `boundary` が入った行の `shift`（補正量）。毎回同じ向きに大きいなら、
  その前のターンの出口がずれている。`"wall_edge": false` にすると記録だけになるので、補正の有無で比べられる

## 経路の約束（シミュレータと同じ）

- ターンは「基準点 → 基準点」の動作。大回り90°・180°・入出45°・入出135° の縦横側の基準点は区画中央、
  小回り90° は区画の辺、斜め側は区画の辺の中点。実機のスラロームの入口・出口（`slalom::Anchor`）が同じ点を指す前提で、
  直線はソルバーが出す基準点の間の長さをそのまま積む
- 経路は (0,0) の区画中央から始まり（置いた位置からそこまでの `90 − START_MM` を最初の直線に足す）、ゴール区画の中央で終わる
- パラメータから計算した各ターンの出口は、経路の約束の出口から 1〜18mm ずれている（500mm/s。スラロームの設計の
  滑りの補正を含む）。実機で走って位置がずれるなら、まずここを疑う
